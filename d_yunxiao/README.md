# dsh-yunxiao

适用于 DeepSeek Harness 的轻量云效工作台插件。它参考了 `python-task` 的云效 OpenAPI 封装和 `card-study` 的工作台流程，但移除了 FastAPI、Vue、Element Plus、SQLAlchemy、数据库、定时采集、通知规则和 Webhook 接收。

## 能力

- 入口：集成到 Harness 左侧栏底部，打开后占用框架预留的右侧列，不以悬浮按钮或全屏遮罩展示；可拖拽左边缘调整宽度，并在浏览器中记住上次宽度。
- 页面：工作台分为“缺陷”“流水线”“设置”三个页签，默认进入缺陷页；缺陷通知配置与未处理数展示在缺陷页底部，账号、当前项目等配置集中在设置页。样式提供跟随系统的浅色/深色两套配色。
- 账号：维护多个云效组织 ID 与个人访问令牌，切换当前账号。
- 项目：读取当前账号可访问的项目，并为每个账号记住当前项目；设置页可为当前项目绑定一个 DSH 工作区（读取 Harness 工作区注册表，按账号+项目分别保存），绑定后即可从缺陷列表一键处理缺陷到该工作区的会话。
- 缺陷：按创建时间从新到旧分页，按状态/负责人自动筛选（不选择即不限制）；状态筛选选项在进入缺陷页时按项目拉取全部缺陷工作项类型的工作流状态（按名称去重，查询时携带同名状态的各个 ID，避免不同类型下同名状态漏筛），并合并最近缺陷中出现的状态；接口异常时退回“最近缺陷 + 首条缺陷工作流”的结果；列表和详情中的状态均为选择后立即修改并刷新列表；“待确认”“处理中”“再次打开”的整条缺陷卡片分别使用柔和的琥珀、蓝、玫红差异色，其余状态保持默认；支持查看描述/评论/附件，并以当前云效账号发布评论；云效附件直链有时效性，附件列表提供“打开/下载”按钮，点击时实时换取新的下载地址（失败时退回详情快照地址），下载优先以原文件名保存，跨域受限时回退新窗口打开；描述与评论内的内联图片加载失败时也会自动换取新地址重试一次；详情展示创建人、最近修改人与更新时间，并可在详情内直接下拉更换负责人（候选来自项目成员列表，保存后同步刷新列表和最近修改人信息）；修改状态或负责人成功返回后约半秒再自动刷新列表，避开云效搜索索引的短暂延迟，避免列表闪回修改前的结果。
- 缺陷处理：仅“待确认”“再次打开”两种状态的缺陷提供“草稿”“处理”两个直达按钮，列表与详情中均有（详情中位于负责人右侧，不弹窗直接执行），“处理”即原“立即处理”，两者都会调用缺陷详情接口；随后在项目绑定的 DSH 工作区新建（或复用空白）会话，带入缺陷标题与描述/附件中的图片（宿主侧换取直链并转 base64，最多 8 张，单张失败自动跳过）——正文只保留缺陷标题，描述仅在含文字时附在“缺陷描述”之后（纯图片描述不再显示该字样），编号、状态、负责人、附件列表和评论不带入；“草稿”只填入会话输入框不自动发送，“处理”直接发送并切换到该会话；未绑定工作区时提示前往设置页绑定。
- 缺陷通知：可按项目开启 Windows 系统通知、选择负责人和轮询间隔；自动解析并保存“待确认/再次打开”的状态 ID，每轮分别带两个状态条件查询一次（均按最后修改时间、第一页、最多 100 条），合并结果后统一按 ID 判断，并用每轮完整结果替换内存 ID 集合（空结果会重置为空，离开目标状态后再次进入可重新提醒）；Harness 桌面端每轮只提交一条 Windows 原生 Toast 提醒（无需浏览器授权弹窗，不再叠加 Web 通知横幅，避免同一桌面出现两条重复提醒）；原生通道失败时回退为 Web 通知；其他环境按 Web 通知或 Windows 后端能力回退；提供常驻内部通知弹窗、“测试内部通知”、“测试 Windows 通知”、“打开 Windows 通知设置”和“立即检查”，同时显示最近命中数、新增数、通知权限、实际通道与最近调用结果；点击“查看缺陷”会切换到缺陷页并打开第一条新增缺陷的详情；侧栏入口的红色角标与最近一轮检查的未处理数保持一致（即缺陷页“缺陷通知”卡片显示的“当前 X 条未处理”），缺陷处理完或关闭通知后自动清零消失。
- 流水线：组织级列表、详情、代码源与分支、运行记录、阶段/任务、日志，以及手动运行；运行表单会自动加载 Codeup 分支（含 SSH 形式仓库地址），单分支代码源使用可输入的分支框（从已加载分支中选择或手动输入任意分支名），分支模式下支持在列表外手动添加分支；未识别到仓库地址的代码源会提示将使用流水线默认分支，不再静默丢弃。运行表单不接收环境变量。
- 模型工具：`yunxiao_list_defects` 和 `yunxiao_list_pipelines`，默认读取工作台的当前账号与项目。
- 离线回退：项目、最近一次缺陷列表和流水线列表写入文本缓存；OpenAPI 暂时失败时展示缓存并标记时间。

插件不提供消息回调、Webhook 接收、通知规则或后台定时采集。

## 数据存储

默认数据文件为 Harness 启动工作目录下的：

```text
dsh-yunxiao.data.json
```

它是可直接查看、备份和编辑的 UTF-8 JSON 文件，不需要数据库。写入时先生成临时文件再原子替换，避免中途退出留下半个 JSON。

重要：个人访问令牌也会保存在这个文本文件中。Host 不会把令牌返回给浏览器，但文件本身不是加密保险箱。请限制文件访问权限，不要提交到 Git，也不要放入公开同步目录。如果部署环境要求加密凭据，应改用 Harness credentials 服务或操作系统密钥存储。

## 安装与更新

以下命令均在插件仓库根目录（即包含 `d_yunxiao` 目录的那一层）执行，命令中只使用仓库相对路径。

首次安装或改动后重新安装：

```powershell
# 从仓库目录安装（首次安装、或换用另一份源码目录时执行）
dsh plugin --profile web add -w ./d_yunxiao

# 校验组合配置中出现 dsh-yunxiao
dsh --profile web --dump-config
```

卸载：

```powershell
dsh plugin --profile web remove -w dsh-yunxiao
```

注意事项：

- 所有 `dsh plugin --profile web add/remove` 命令都必须带 `-w` 参数。web profile 目录本身是一个 pnpm workspace 根，缺少它时会报 `ERR_PNPM_ADDING_TO_ROOT` / `ERR_PNPM_REMOVING_ROOT`。
- 安装是 link 形式：profile 直接引用仓库中的插件源码目录。日常只修改 `dist/index.js` 或 `dist/client.js` 后，重启 Harness 实例即可加载最新代码；仅当插件的 `package.json` 变化（名称、入口、依赖、版本元数据等影响安装结果的字段）时才需要重新 `add`。
- 安装或重新安装后，必须重启正在运行的 Harness Web/Desktop 实例才能生效。

验证组合配置中应出现：

```yaml
- id: dsh-yunxiao
  name: dsh-yunxiao
```

安装后重启正在运行的 Harness Web/Desktop 实例。左侧栏底部会出现“云效工作台”入口，侧栏折叠时显示“云”图标。工作台固定在右侧列中打开，关闭后聊天区恢复完整宽度。

## 配置

可在 profile 的 `cordis.patch.yml` 中覆盖整行配置：

```yaml
- override:
    id: dsh-yunxiao
    name: dsh-yunxiao
    config:
      dataFile: 'D:/private/dsh-yunxiao.data.json'
      apiBaseUrl: 'https://openapi-rdc.aliyuncs.com'
      timeoutMs: 45000
      cacheMaxItems: 100
```

`apiBaseUrl` 只接受 HTTPS。`cacheMaxItems` 限制列表缓存数量，范围 10–500。

## 云效令牌权限

按实际使用功能给个人访问令牌授予最小权限：

- 项目读取；
- 工作项读取；
- 修改缺陷状态时需要工作项写入；
- 在详情中更换缺陷负责人时需要工作项写入，读取项目负责人候选列表时需要项目成员只读权限；
- 发布缺陷评论时需要工作项评论读写权限；
- 流水线读取；
- 手动运行流水线时需要流水线运行权限；
- 读取 Codeup 分支时需要代码库/分支读取权限。

只使用查看功能时无需授予写权限。

## 开发验证

在插件仓库根目录运行：

```powershell
node --check .\d_yunxiao\dist\index.js
node --check .\d_yunxiao\dist\client.js
npm test --prefix .\d_yunxiao
npm pack .\d_yunxiao --dry-run
```

实现遵循 Harness 的可安装组合包结构：`dsh.bundle.patch` 挂载 Host 插件，`dsh.client` 在 Web 表面即时加载无框架 Client。参考：[DeepSeek Harness 插件基础](https://deepseek-harness.github.io/deepseek-harness/develop/basic/)。
